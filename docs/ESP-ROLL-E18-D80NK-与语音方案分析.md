# ESP-ROLL 加装 E18-D80NK、扬声器与板载麦克风分析报告

生成日期：2026-04-29  
分析范围：`d:\esprollCODE` 整个文件夹内的源码、配置、说明文档、XIAO ESP32S3 Sense 原理图/引脚表、ESP-ROLL 机器人主板原理图、Gerber/BOM/贴片文件、既有中文报告与压缩包内容列表。

## 1. 结论先行

1. **E18-D80NK 可以接，但建议优先接 `GPIO44 / D7 / RX`。**  
   这是当前项目配置里唯一比较干净的 XIAO 标准侧边引脚。接入时要确认 E18-D80NK 的输出电平不能超过 3.3V；如果输出端被模块上拉到 5V，需要加电平转换、分压，或改为 3.3V 上拉的开漏/集电极输出。

2. **板载麦克风可以用，不需要额外占用 XIAO 标准排针。**  
   文件夹里的 XIAO ESP32S3 Sense 原理图和引脚表都指向板载 PDM 麦克风：`GPIO41 = PDM_DATA`，`GPIO42 = PDM_CLK`。当前代码的 `camera_pins.h` 也已经为 XIAO 定义了 `I2S_SD 41`、`I2S_WS 42`、`I2S_SCK -1`，表示使用 PDM 麦克风。

3. **真正能播放语音的扬声器不能直接接 GPIO，需要 I2S 功放模块。**  
   主板上已有 `BUZZER1`，BOM 里是 `FT12095-G/5V` 蜂鸣器，这只能蜂鸣提示，不适合语音聊天。语音输出建议使用 MAX98357A 这类 I2S 功放加小喇叭。

4. **如果“扬声器”要求装在机器人本体上，同时还保留 SD 卡、双电机、板载麦克风和 E18-D80NK，当前主板空闲引脚不够。**  
   PDM 麦克风不能和 I2S 功放共享时钟，I2S 功放还要 3 个 GPIO：BCLK、LRCLK、DIN。现有配置下可直接剩下的只有 `GPIO44 / D7`。要同时上 E18 和本体语音扬声器，必须牺牲现有功能或加辅助板。

5. **当前项目支持“对讲/音频流”，不等于已经支持 AI 语音聊天。**  
   代码里有浏览器麦克风、浏览器扬声器、ESP 端麦克风、I2S 功放和 intercom 逻辑；但没有 ASR、TTS、LLM 或云端语音聊天后端。如果你说的“语音聊天”是像手机网页和机器人互相说话，项目基础已经有；如果是“机器人像智能音箱一样聊天”，还要增加服务器/API 与音频编解码流程。

## 4. E18-D80NK 避障接入分析

### 4.1 硬件可行性

E18-D80NK 作为避障传感器，通常只需要：

- 电源：VCC
- 地：GND
- 数字输出：OUT

因此从引脚数量上看，只要 1 个输入 GPIO。结合当前项目，引脚上最合理的是：

**推荐接法：**

| E18-D80NK | 建议连接 |
|---|---|
| VCC | 按模块规格接 5V 或适配电源。若机器人只有单节锂电直供，需确认 E18 在当前电压下能稳定工作 |
| GND | 机器人 GND |
| OUT | `GPIO44 / D7 / RX`，建议串 1k-4.7k 保护电阻，必要时加电平转换或分压 |

### 4.2 电平风险

ESP32-S3 GPIO 不能承受 5V 输入。E18-D80NK 的 OUT 必须确认：

- 如果是开漏/开集电极输出：用 10k 上拉到 3.3V，OUT 接 `GPIO44`，这是最稳妥的方式。
- 如果模块 OUT 直接输出 5V 高电平：必须用分压或电平转换后再进 ESP32-S3。
- 传感器电源如果必须 5V，而机器人电池是 3.7V 单节锂电，建议加升压模块，否则检测距离和稳定性可能下降。

### 4.3 软件可行性

当前项目已有 `pirUse`、`pirPin`、`getPIRval()` 这一套“数字运动传感器”入口，可以先把 E18 当成 PIR/雷达输入：

```txt
pirUse = 1
pirPin = 44
```

但这只能让固件知道“有传感器触发”。真正“避障”还需要增加电机控制逻辑，例如：

- 前进时检测到障碍：立即 `motorSpeed(0)` 停车；
- 保持 200-500 ms 确认，防抖；
- 可选：后退一小段，再左右差速转向；
- 避障输入建议不要放在 ISR 里做复杂动作，ISR 只置位，动作在任务或主循环里执行。

## 5. 扬声器与语音聊天分析

### 5.1 主板已有蜂鸣器不能当语音扬声器

主板 BOM 里有 `BUZZER1`，型号 `FT12095-G/5V`，这是主动蜂鸣器。它适合“滴滴声”和报警提示，不适合播放语音。  
语音输出需要：

- I2S 功放模块，例如 MAX98357A；
- 小喇叭；
- 3 个 GPIO：BCLK、LRCLK、DIN；
- 独立稳定供电，避免电机噪声串入音频。

### 5.2 当前代码怎样驱动扬声器

`audio.cpp` 里已经有 I2S 功放支持：

```txt
mampBckIo  -> I2S BCLK / SCK
mampSwsIo  -> I2S LRCLK / WS
mampSdIo   -> I2S DIN
ampVol     -> 功放音量，0 表示关闭
```

问题在于：XIAO Sense 的板载麦克风是 PDM，代码注释也说明 PDM 麦克风必须和 I2S 功放使用分开的 I2S 通道/引脚。因此本体语音扬声器基本要 3 个额外 GPIO。

### 5.3 当前主板能不能同时加 E18 和本体扬声器

**保留现有功能的情况下，不够。**

当前能比较干净新增的只有 `GPIO44 / D7` 一个脚。E18-D80NK 已经要占一个输入脚；I2S 功放还要三个输出脚，所以不能在“不牺牲功能”的前提下同时完成。

可选方案如下：

| 方案 | 引脚占用 | 优点 | 代价 |
|---|---:|---|---|
| A. 只加 E18，本体不加扬声器，用手机/电脑浏览器当扬声器 | E18 占 `GPIO44` | 最稳，改动少 | 机器人本体不能发声说话 |
| B. 加 E18 + 本体 I2S 扬声器，牺牲若干功能 | E18 1 脚 + 功放 3 脚 | 机器人可本体发声 | 需放弃电池检测/蜂鸣器/灯控等至少 3 项中的一部分 |
| C. 加辅助 ESP32/小扩展板 | 主控只需 UART/I2C 或网络 | 最干净，可扩展 | 硬件复杂度上升 |
| D. 用 DFPlayer Mini | 2 个 UART 脚 | 可播放预录语音 | 不能实时语音聊天，只能放固定音频 |

如果一定要上本体 I2S 功放，可以考虑牺牲现有功能后的一个示例分配：

| 功能 | GPIO | 牺牲项 |
|---|---:|---|
| MAX98357A BCLK | 6 / D5 | 取消主动蜂鸣器 |
| MAX98357A LRCLK | 43 / D6 | 取消 RC 灯控/LED 环控制 |
| MAX98357A DIN | 44 / D7 | 使用原空闲脚 |
| E18-D80NK OUT | 5 / D4 | 取消电池电压检测 |

这只是可行示例，不是唯一方案。实际焊接前建议先用万用表确认 D5、D6、D7、D4 在当前 PCB 上的焊点与现有电路连接关系。

## 6. 板载麦克风怎么用

### 6.1 硬件连接关系

XIAO ESP32S3 Sense 的板载麦克风是 PDM 麦克风。项目内证据一致：

```txt
GPIO41 = PDM_DATA / I2S_SD
GPIO42 = PDM_CLK  / I2S_WS
I2S_SCK = -1      / PDM 模式无独立 SCK
```

所以不需要把外部麦克风接到 D0-D10。它已经在板上，只是当前固件没有编译音频功能。

### 6.2 软件启用步骤

1. 在 `ESP32-CAM_MJPEG2SD/appGlobals.h` 中改：

```cpp
#define INCLUDE_AUDIO true
```

2. 确认 XIAO 板型仍为：

```cpp
#define CAMERA_MODEL_XIAO_ESP32S3
```

3. 编译时启用 PSRAM。README 也说明 ESP32S3 更适合音频录制和 intercom。

4. Web 配置或 `configs.txt` 中建议设置：

```txt
AudActive = 1
micSckPin = -1
micSWsPin = 42
micSdPin  = 41
micGain   = 3 到 6 先试
```

5. 如果只想听到机器人麦克风声音，可先用浏览器扬声器测试，不接本体功放：

```txt
spkrRem = 1
```

6. 如果接了 MAX98357A，再设置：

```txt
mampBckIo = 你分配的 BCLK
mampSwsIo = 你分配的 LRCLK
mampSdIo  = 你分配的 DIN
ampVol    = 3 到 6 先试
```

## 7. 对“语音聊天”的实现边界

当前文件夹里的项目已经具备：

- ESP 端 PDM 麦克风采集；
- I2S 功放输出；
- 浏览器麦克风输入；
- 浏览器扬声器输出；
- WebSocket 传 PCM 音频；
- intercom 对讲基础。

当前文件夹里没有：

- 语音识别 ASR；
- 文本转语音 TTS；
- 大模型聊天接口；
- 面向 AI 语音聊天的后端服务。

因此：

- **人与机器人网页对讲：可基于现有代码启用音频后实现。**
- **机器人 AI 语音聊天：需要新增云端或局域网后端。** ESP32-S3 负责采集/播放音频，把语音送到后端识别和生成回答，再把 TTS 音频回传给 ESP 播放。

## 8. 推荐落地路线

### 阶段 1：最小风险验证

1. 先启用 `INCLUDE_AUDIO true`。
2. 不接本体扬声器，只用 XIAO 板载麦克风 + 浏览器扬声器测试麦克风。
3. 把 E18-D80NK OUT 接到 `GPIO44 / D7`，配置 `pirUse=1`、`pirPin=44`，串口/日志观察触发状态。
4. 确认 E18 输出电平安全后，再写避障逻辑。

### 阶段 2：实现基础避障

1. 在电机控制路径里加入 `obstacleDetected` 状态。
2. 前进状态下触发 E18：立即停车。
3. 延时确认后执行后退/转向动作。
4. 保留摄像头和 SD 卡，不动 `GPIO7/8/9`。

### 阶段 3：决定语音输出方案

优先选择：

- 如果接受手机/电脑播放声音：不加本体功放，保留更多功能。
- 如果必须机器人本体说话：加 MAX98357A，同时牺牲蜂鸣器、灯控、电池检测中的若干项，或增加辅助控制板。

## 9. 最终建议

我建议采用这个组合：

```txt
E18-D80NK OUT -> GPIO44 / D7
板载麦克风 -> GPIO41 / GPIO42，直接启用音频即可
语音播放 -> 第一版先用浏览器扬声器
本体扬声器 -> 第二版再加 MAX98357A 或辅助板
```

这样最符合当前文件夹里的硬件和代码现状：不破坏电机、SD 卡、摄像头和电池检测，能先把避障和麦克风跑通。等确认交互流程稳定后，再决定是否牺牲蜂鸣器/灯控/电池检测来换本体扬声器，或者直接上辅助板。
